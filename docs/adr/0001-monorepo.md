# 0001. Один репозиторий на все микросервисы

**Статус:** принято

## Контекст
Проект учебный, разработчик один. Изменения часто задевают несколько сервисов сразу
(формат JWT затрагивает auth-service, api-gateway и billing-service).

## Варианты
1. Репозиторий на каждый сервис (polyrepo).
2. Один репозиторий, каждый сервис в своей папке (monorepo).

## Решение
Monorepo. У каждого сервиса свой `pom.xml`, Dockerfile и база.
Импортировать классы одного сервиса в другой **запрещено**: сервисы общаются только по HTTP/Kafka.

## Последствия
+ одно изменение = один коммит/PR по всей системе; общий docker-compose и документация рядом с кодом.
− в CI нужен фильтр по путям, чтобы не пересобирать все сервисы на каждый коммит.
